# Pull request queue design

Give people one place to find agent-submitted GitHub pull requests without finding the chat that produced them. Add a **PR Queue** side panel to the existing client plugin; use the existing room side-panel surface rather than a new global navigation surface. The queue aggregates joined rooms from the signed-in Matrix account, not every room on the server.

Reuse the existing backend plugin and Matrix state that already indexes each thread's pull requests. Thread links, including automatically linked creations, count as submissions. An explicit `pull_requests(action="submit", url=...)` action also works outside a thread in a room. The wire format for a room-only submission is the existing `com.mindroom.thread.pull_request` event, key `[null,"owner/repo#number"]` in compact JSON, with the existing `url`, `set_by`, `set_at` content. Existing thread keys and readers keep their meaning. An empty content is a tombstone, never a submission.

A server-wide queue would need new authorization, storage and a status worker. A room-only queue would make people visit multiple rooms. Aggregating joined-room state in the client reuses Matrix membership and the existing read-only GitHub query path. It requires no GitHub writes or additional credentials. Reuse the source room's GitHub access rather than sending a repository from one room to another room's server for lookup.

Deduplicate canonical GitHub PR identities. Use a stable source room for a duplicate, preferring the room where the panel opened, then the newest submitted link, then room ID to break ties. Keep selected sources responsive to joins, leaves and state updates. Show a PR link by repository and number even when its status is unavailable. Distinguish Closed without merge from Merged; keep closed-unmerged entries outside Done. Preserve last good status on a transient refresh failure, but do not use data after an authorization refusal or account change.

Refresh summaries on opening or focusing the panel and periodically while visible, using existing rate-limit and caching behavior rather than loading files, checks or diffs. Once GitHub confirms a valid merge timestamp, move the PR to a collapsed **Done** disclosure. At `mergedAt + 12h` remove it from the queue view, including when an already-merged PR was submitted late. While visible, a timer handles expiry without another GitHub request. Leave Matrix thread history intact. Reconcile on next open when no client panel was running; no background server worker or deletion of source records.
